## Notes
- **Loader record shape (from `1.1.1`):** `{ key, name, letter, status, sc, skb, skbPath, horizons, site, hasSc, hasSkb }`. Normalized `skb` already converts `"NA"` -> `null`, unwraps `HORIZONS`/`SITE`, and strips leading `<HEADER>:` prefixes from section `content`.
- **Stylesheet classes (from `1.1.2`):** `.osd-page`, `.osd-chrome`, `.osd-header`, `.osd-meta`, `.osd-location` (`white-space: pre-wrap`), `.osd-downloads`, `.osd-narrative`, `.osd-title`, `.osd-section`, `.osd-section-label`, `.osd-horizon`, `.osd-horizon-name` (`white-space: pre`), `.osd-pedon-layout` > `.osd-pedon-text` + `.osd-pedon-sketch`, `.osd-footer`, `.no-print`.
- **NSSH section order (from `AMADOR` reference & `GUIDELINES.R`):** `TAXONOMIC CLASS`, `TYPICAL PEDON`, `TYPE LOCATION`, `RANGE IN CHARACTERISTICS`, `COMPETING SERIES`, `GEOGRAPHIC SETTING`, `GEOGRAPHICALLY ASSOCIATED SOILS`, `DRAINAGE AND PERMEABILITY`, `USE AND VEGETATION`, `DISTRIBUTION AND EXTENT`, `REGIONAL OFFICE`, `ORIGIN`, `REMARKS`, `ADDITIONAL DATA`. Section label uses `secObj.section ?? sectionKey`.
- **Typical Pedon formatting:** Split `TYPICAL PEDON.content` lines before the first horizon line for the pedon intro text, then render each item in `record.horizons` with `<span class="osd-horizon-name">` holding 4-space indent + `h.name` followed by the remainder of `h.narrative`. If `record.horizons` is empty, render `TYPICAL PEDON.content` lines directly.
- **Constraints honored:** Will not modify `src/loader/*`, `src/styles/usdastyle.css`, `src/render/profile-sketch.js`, or `docs/`. Temporary test outputs will stay inside `.development/` (and be cleaned up) or OS temp dir.
